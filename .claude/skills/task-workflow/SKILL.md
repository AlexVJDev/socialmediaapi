# Процесс работы над задачей

Файлы задачи — в `docs/md/<task-number>/`. Описание задачи — `Descr-<task-number>.md` (или `.pdf`), страницы wiki — `Descr-<N>.pdf`.

## 0. Перед любым шагом
1. Прочитать `decisions.md` (если есть). Это источник правды; остальное — черновики.
2. Файлы из `archive/` не читать и не использовать как основание.
3. Если черновик противоречит `decisions.md` или коду пользователя — не исправлять код, а спросить.
4. Отработанные файлы (старые fix, Readme, task-manual, примеры) переносить в `archive/` задачи.

## 1. decisions.md — журнал решений
Создаётся вместе с первым `fix.md`. Формат — одна таблица, одна строка на решение:

| ID | Решение (1–2 строки) | Источник | Статус |
|---|---|---|---|
| Р1-1 | … | ответ в fix.md, 10.11.2026 | действует |
| Р2-7 | … | Readme-2 | заменено Р9-1 |

- Принятый ответ из fix.md / Readme — сразу строкой сюда.
- Указание пользователя в чате — сразу строкой сюда, в ответе: «записал как Р-…».
- Изменённое решение: старой строке статус «заменено Р-x», новой — «действует». Строки не удалять.
- Без обоснований и истории: подробности — в `notes.md`.

## 2. fix.md — вопросы пользователю
Если `fix.md` уже есть — разобрать ответы, перенести в `decisions.md`, перейти к шагу 3.

Структура (строго в этом порядке):
1. `Режим Ментора: ДА/НЕТ` (по умолчанию ДА).
2. `## Требует ответа` — не больше 10 вопросов за раунд. На вопрос не больше 4 строк:
   вопрос, варианты (если есть), **Рекомендация:** одной строкой, `Ответ: Принимается` (по умолчанию).
   Сначала вопросы, которые меняют API или структуру, потом остальные.
3. `## К сведению` — опечатки и недочёты в описании, которые не требуют решения. Кратко, списком.

Не включать в fix.md: анализ, адреса и примеры ESB, историю решений — это в `notes.md`.
Каждое расхождение с образцом (параметры, формат ответа, обёртка, структура) — отдельный вопрос
«как в образце X или как в Y?» с рекомендацией.

Следующий раунд вопросов — новый раздел `## Раунд N` сверху; отвеченные раунды сворачивать в одну строку
«ответы перенесены в decisions.md Р<N>-1…Р<N>-k».

## 3. Readme.md
Только если пользователь его просит или задача большая. Не дублирует fix.md и decisions.md:
краткое описание итоговой реализации (эндпоинты, модули, поток данных) со ссылками на ID решений.

## 4. План
- `Режим Ментора: НЕТ` → файлы `task-XX.md` для ИИ.
- `Режим Ментора: ДА` → один `task-manual.md` для пользователя.

Общее для обоих:
- В начале: число изменяемых и новых файлов, разделы `## Где будут файлы` и `## Файлы` (как в `docs/md/task-21-example.md`).
- Порядок — от независимых к зависимым (модель → порт → адаптер → сервис → контроллер).
- Каждый пункт: номер, файл, слой, зачем (1 строка), что сделать, ссылка на ID решения из `decisions.md`.
- Подзадача — законченный кусок, до ~15 файлов.
- После составления — попросить пользователя проверить и ждать ответа.

Если план переделывается — старый файл перенести в `archive/`, а не добавлять пометку сверху.
Если пользователь сделал пункт иначе — записать решение в `decisions.md`, последующие пункты плана править
только по его команде.

## 5. Выполнение и проверка
- Выполнять проверенные подзадачи по порядку, только по команде.
- При проверке кода пользователя: сначала `decisions.md`, потом код. Расхождение с планом — вопрос, а не правка.
- Тесты минимальные: архитектура + happy-path.
- По окончании напомнить про `ApplicationModulesTest` (не запускать без команды).

## 6. Ручные тесты (последний пункт плана)
a) `manual-test-curl.md` — готовый к запуску скрипт (curl/sh): проверяет новый функционал и выводит итог OK/FAIL.

b) `manual-test-bruno.md` — для каждого запроса: curl (token `{{collection_dev_token}}`, base `{{baseUrl}}`),
   метод, JSON запроса, ожидаемый ответ. Плюс готовая коллекция Bruno в папке `bruno/<task-number>/`.

## 7. Код-ревью по задаче
- Эталон — `decisions.md` и последние указания пользователя, не fix.md / task-manual.
- Находка «код не соответствует плану» — допустима только если код противоречит действующему решению.
- Результат — `code-review.md`: таблица «№ | файл:строка | проблема (1 строка) | рекомендация | Ответ».
