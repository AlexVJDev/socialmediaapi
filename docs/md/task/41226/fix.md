# 41226 — Swagger UI для OpenAPI. Вопросы

Режим Ментора: ДА

## Раунд 1 — Требует ответа

**1. Публикация многофайлового контракта.** `openapi.yaml` ссылается на `./paths/*.yaml`, а те — на `../schemas`, `../responses`; в уроке копируется только `openapi.yaml`, и тогда UI не разрешит ссылки.
Варианты: а) копировать `openapi.yaml` + `paths/`, `schemas/`, `responses/` в `static/openapi` с сохранением структуры (`modules/` и `*.md` — нет), Swagger UI сам подгрузит относительные `$ref`; 
б) только `openapi.yaml`, как в уроке; в) собирать на сборке один файл (bundle).
**Рекомендация:** а) — исходник по-прежнему один (`docs/api`), без второй копии и без доп. плагина.
Ответ: Принимается

**2. Bearer Security Scheme.** В контракте уже есть `userIdHeader` (`X-User-Id`) — кнопка Authorize появится и от неё; Keycloak/Spring Security в проекте нет.
Варианты: а) добавить `bearerAuth` в `components.securitySchemes`, глобальный `security` не задавать (операции не меняются); 
б) как в уроке — ещё и глобальный `security: - bearerAuth: []` (friendships начнут «требовать» токен, который никто не проверяет); в) не добавлять.
**Рекомендация:** а) — пункт урока выполнен, контракт не обещает проверку, которой нет.
Ответ: Принимается

**3. Раздел `servers`.**
Варианты: а) как в уроке — `http://localhost:8080`, «Локальное окружение»; б) `url: /` — запросы Try it out идут на тот же хост, с которого открыт UI.
**Рекомендация:** б) — работает в любом окружении и на любом порту.
Ответ: Принимается

**4. Автоматическое описание `/v3/api-docs`** (springdoc строит его по контроллерам — второй источник контракта).
Варианты: а) оставить — UI его не использует (`url` + `disable-swagger-default-url`); б) отключить `springdoc.api-docs.enabled: false`.
**Рекомендация:** б), если UI после этого открывается (проверить при запуске); иначе — а).
Ответ: Принимается

**5. Отключение через `SWAGGER_UI_ENABLED`.**
Варианты: а) как в уроке — только `springdoc.swagger-ui.enabled: ${SWAGGER_UI_ENABLED:true}` (файл `/openapi/openapi.yaml` остаётся доступен как статика); б) закрывать и статический файл.
**Рекомендация:** а) — по уроку; контракт не секрет.
Ответ: Принимается

**6. Автотест.**
Варианты: а) один E2E-класс (наследник `E2ETest`): `GET /openapi/openapi.yaml` → 200 и содержит `/api/v1/friendship-offer/create`; `GET /openapi/paths/friendship-offer-create.yaml` → 200; `GET /swagger-ui.html` → 200 (после редиректа); б) без автотеста, только ручная проверка.
**Рекомендация:** а) — минимальный happy-path, ловит поломку копирования ресурсов.
Ответ: Принимается

**7. Ручные тесты.**
Варианты: а) `manual-test-curl.md` (доступность файла, UI, `/v3/api-docs`, create offer) + чек-лист проверки в браузере (Authorize, Try it out); Bruno не делать — нового API нет; б) curl + Bruno по полной схеме.
**Рекомендация:** а).
Ответ: Принимается

**8. Кто пишет код.**
Варианты: а) как в 41224 (Р4-7) — пункты плана выполняет Claude по одному по команде, пользователь проверяет; б) код пишет пользователь по `task-manual.md`.
**Рекомендация:** а).
Ответ: Принимается

## К сведению
- Spring Boot 4.1.1 → springdoc 3.x (в уроке `3.1.1`); в локальном `~/.m2` только 2.x — будет скачан. Совместимость проверим сборкой; при несовместимости — ближайшая 3.x.
- Конфиг — в `application.yml` (`application.properties` в проекте нет).
- Блок `<resources>` в pom заменяет ресурсы по умолчанию, поэтому `src/main/resources` в нём объявляется явно (как в уроке).
- Spring Security в проекте нет — `SecurityFilterChain` настраивать не нужно.
- `@Operation`/`@ApiResponse` в контроллерах нет, генератор их не пишет (`annotationLibrary none`) — ничего убирать не надо.
- Try it out для create offer (п. 6 урока): операции friendships без `security`, токен/заголовок не нужен.
- `modules/*.yaml` (входы генератора) не меняются — Bearer-схема и `servers` нужны только в `openapi.yaml`.
- Коммит (п. 9 урока) делает пользователь.
