# Создание предложения дружбы

Метод создаёт предложение дружбы от одного пользователя к другому.

При успешном создании предложения:

- создаётся заявка в состоянии `PENDING`;
- инициатор автоматически подписывается на получателя;
- дружба между пользователями ещё не создаётся — она появится только после принятия предложения.

## HTTP-запрос

```http
POST /api/offer-friendships/create
Content-Type: application/json
```

## Тело запроса

Тело запроса содержит идентификаторы пользователя-инициатора и пользователя-получателя.

```json
{
  "fromUserId": "0b6f3c9e-6a1d-4c2e-9f5a-2d7b8e1c4a01",
  "toUserId": "5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22"
}
```

### Поля запроса

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `fromUserId` | `string (uuid)` | Да | Идентификатор пользователя, который отправляет предложение дружбы. |
| `toUserId` | `string (uuid)` | Да | Идентификатор пользователя, которому отправляется предложение дружбы. |

## Успешный ответ

Если предложение создано, API возвращает статус `201 Created` и данные созданной заявки.

```http
HTTP/1.1 201 Created
Content-Type: application/json
```

```json
{
  "id": "9c4e1b77-3f2a-4d6c-8b0e-1a5f7d2c3e44",
  "fromUserId": "0b6f3c9e-6a1d-4c2e-9f5a-2d7b8e1c4a01",
  "toUserId": "5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22",
  "status": "PENDING",
  "createdAt": "2026-09-22T10:15:00Z"
}
```

### Поля ответа

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `string (uuid)` | Идентификатор созданного предложения дружбы. |
| `fromUserId` | `string (uuid)` | Идентификатор пользователя-инициатора. |
| `toUserId` | `string (uuid)` | Идентификатор пользователя-получателя. |
| `status` | `string` | Текущее состояние предложения. Для новой заявки — `PENDING`. |
| `createdAt` | `string` | Дата и время создания предложения в формате ISO 8601. |

## Правила обработки

- Нельзя отправить предложение дружбы самому себе.
- Повторное предложение для уже существующей заявки в состоянии `PENDING` не создаёт дубликат: API возвращает `204 No Content` без тела.
- Если предложение уже принято, повторное создание завершается конфликтом.
- Если предложение было отклонено, повторное создание завершается конфликтом.

## Идемпотентность

Повторный HTTP-запрос возможен, если клиент не получил ответ из-за сетевой ошибки.

- Повторное создание предложения в состоянии `PENDING` не создаёт вторую заявку.
- Повторное создание не создаёт вторую подписку инициатора на получателя.
- Если предложение уже принято и находится в состоянии `ACCEPTED`, повторный вызов завершается конфликтом, потому что принятое предложение нельзя вернуть в `PENDING`.
- Если предложение уже отклонено и находится в состоянии `REJECTED`, повторный вызов завершается конфликтом, потому что отклонённое предложение нельзя автоматически вернуть в `PENDING`.

## Возможные ошибки

Тело ответа с ошибкой: `{"code": "...", "message": "..."}`.

| HTTP-статус | `code` | Ситуация |
| --- | --- | --- |
| `400 Bad Request` | `INVALID_FRIENDSHIP_OFFER_REQUEST` | Некорректное тело запроса, отсутствуют обязательные поля, идентификатор не является UUID или `fromUserId` совпадает с `toUserId`. |
| `404 Not Found` | `USER_NOT_FOUND` | Пользователь-инициатор или пользователь-получатель не найден. |
| `409 Conflict` | `FRIENDSHIP_OFFER_ALREADY_ACCEPTED` | Заявка в этом направлении уже принята. |
| `409 Conflict` | `FRIENDSHIP_OFFER_ALREADY_REJECTED` | Заявка в этом направлении уже отклонена. |

Пример:

```http
HTTP/1.1 409 Conflict
Content-Type: application/json
```

```json
{
  "code": "FRIENDSHIP_OFFER_ALREADY_REJECTED",
  "message": "Предложение дружбы уже отклонено"
}
```
