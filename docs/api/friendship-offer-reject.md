# Отклонение предложения дружбы

Метод отклоняет существующее предложение дружбы, которое находится в состоянии `PENDING`.

При успешном отклонении предложения:

- состояние заявки меняется на `REJECTED`;
- дружба между пользователями не создаётся;
- обратная подписка получателя на инициатора не создаётся;
- существующая подписка инициатора на получателя сохраняется.

## HTTP-запрос

```http
POST /api/v1/friendship-offer/reject
Content-Type: application/json
```

## Тело запроса

```json
{
  "offerId": "9c4e1b77-3f2a-4d6c-8b0e-1a5f7d2c3e44",
  "actorId": "5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22"
}
```

### Поля запроса

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `offerId` | `string (uuid)` | Да | Идентификатор отклоняемого предложения дружбы. |
| `actorId` | `string (uuid)` | Да | Пользователь, выполняющий действие, — получатель предложения. До подключения аутентификации (Keycloak) передаётся в теле, затем будет браться из токена. |

## Успешный ответ

Если предложение успешно отклонено, API возвращает статус `200 OK` и данные обновлённой заявки.

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "id": "9c4e1b77-3f2a-4d6c-8b0e-1a5f7d2c3e44",
  "fromUserId": "0b6f3c9e-6a1d-4c2e-9f5a-2d7b8e1c4a01",
  "toUserId": "5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22",
  "status": "REJECTED",
  "createdAt": "2026-09-22T10:15:00Z",
  "rejectedAt": "2026-09-22T10:20:00Z"
}
```

### Поля ответа

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `string (uuid)` | Идентификатор предложения дружбы. |
| `fromUserId` | `string (uuid)` | Идентификатор пользователя-инициатора. |
| `toUserId` | `string (uuid)` | Идентификатор пользователя, который отклонил предложение. |
| `status` | `string` | Текущее состояние предложения. После успешного отклонения — `REJECTED`. |
| `createdAt` | `string` | Дата и время создания предложения в формате ISO 8601. |
| `rejectedAt` | `string` | Дата и время отклонения предложения (время смены статуса, `updated_at`) в формате ISO 8601. |

## Правила обработки

- Отклонить можно только существующее предложение дружбы.
- Отклонить предложение может только его получатель (`actorId` = `toUserId`). Для любого другого пользователя предложение считается не найденным (`404`): существование чужой заявки не раскрывается.
- Предложение должно находиться в состоянии `PENDING`.
- После отклонения состояние предложения меняется на `REJECTED`.
- Отклонение не создаёт связь дружбы и обратную подписку получателя на инициатора.
- Подписка инициатора на получателя, созданная при отправке предложения дружбы, сохраняется.
- Уже принятое предложение нельзя отклонить, потому что дружба уже создана.
- При одновременных принятии и отклонении одного предложения статус меняет только одна команда, вторая получает `409`.

## Идемпотентность

Повторный HTTP-запрос возможен, если клиент не получил ответ из-за сетевой ошибки.

- Если предложение уже находится в состоянии `REJECTED`, повторный вызов возвращает `409 FRIENDSHIP_OFFER_ALREADY_REJECTED` и не меняет данные; подписка инициатора не удаляется.
- Если предложение находится в состоянии `ACCEPTED`, попытка отклонить его возвращает `409 FRIENDSHIP_OFFER_ALREADY_ACCEPTED`: дружба не отменяется.
- Если предложение не найдено, повторный вызов возвращает `404 FRIENDSHIP_OFFER_NOT_FOUND`.

## Возможные ошибки

Тело ответа с ошибкой: `{"code": "...", "message": "..."}`.

| HTTP-статус | `code` | Ситуация |
| --- | --- | --- |
| `400 Bad Request` | `INVALID_FRIENDSHIP_OFFER_REQUEST` | Некорректное тело запроса, отсутствует `offerId` или `actorId`, идентификатор не является UUID. |
| `404 Not Found` | `FRIENDSHIP_OFFER_NOT_FOUND` | Предложения нет или `actorId` не является его получателем. |
| `409 Conflict` | `FRIENDSHIP_OFFER_ALREADY_ACCEPTED` | Предложение уже принято. |
| `409 Conflict` | `FRIENDSHIP_OFFER_ALREADY_REJECTED` | Предложение уже отклонено. |
