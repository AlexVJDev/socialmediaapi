# Принятие предложения дружбы

Метод принимает существующее предложение дружбы, которое находится в состоянии `PENDING`.

При успешном принятии предложения в одной транзакции:

- состояние заявки меняется на `ACCEPTED`;
- между пользователями создаётся дружба;
- получатель предложения подписывается на инициатора, если такой подписки ещё нет;
- в результате пользователи имеют взаимную подписку.

## HTTP-запрос

```http
POST /api/v1/friendship-offer/accept
Content-Type: application/json
```

## Тело запроса

```json
{
  "offerId": "9c4e1b77-3f2a-4d6c-8b0e-1a5f7d2c3e44",
  "actorId": "5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22"
}
```

### Поля запроса

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `offerId` | `string (uuid)` | Да | Идентификатор принимаемого предложения дружбы. |
| `actorId` | `string (uuid)` | Да | Пользователь, выполняющий действие, — получатель предложения. До подключения аутентификации (Keycloak) передаётся в теле, затем будет браться из токена. |

## Успешный ответ

Если предложение успешно принято, API возвращает статус `200 OK` и данные обновлённой заявки.

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "id": "9c4e1b77-3f2a-4d6c-8b0e-1a5f7d2c3e44",
  "fromUserId": "0b6f3c9e-6a1d-4c2e-9f5a-2d7b8e1c4a01",
  "toUserId": "5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22",
  "status": "ACCEPTED",
  "createdAt": "2026-09-22T10:15:00Z",
  "acceptedAt": "2026-09-22T10:20:00Z"
}
```

### Поля ответа

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `string (uuid)` | Идентификатор предложения дружбы. |
| `fromUserId` | `string (uuid)` | Идентификатор пользователя-инициатора. |
| `toUserId` | `string (uuid)` | Идентификатор пользователя, который принял предложение. |
| `status` | `string` | Текущее состояние предложения. После успешного принятия — `ACCEPTED`. |
| `createdAt` | `string` | Дата и время создания предложения в формате ISO 8601. |
| `acceptedAt` | `string` | Дата и время принятия предложения (время смены статуса, `updated_at`) в формате ISO 8601. |

## Правила обработки

- Принять можно только существующее предложение дружбы.
- Принять предложение может только его получатель (`actorId` = `toUserId`). Для любого другого пользователя предложение считается не найденным (`404`): существование чужой заявки не раскрывается.
- Предложение должно находиться в состоянии `PENDING`.
- После принятия состояние предложения меняется на `ACCEPTED`.
- Принятие создаёт связь дружбы между инициатором и получателем.
- Принятие создаёт обратную подписку получателя на инициатора, если она ещё не существует.
- Для пары пользователей существует не больше одного предложения (в любом направлении), поэтому принятие не может создать вторую дружбу.
- Отклонённое предложение нельзя принять.
- При одновременных принятии и отклонении одного предложения статус меняет только одна команда, вторая получает `409`.

## Идемпотентность

Повторный HTTP-запрос возможен, если клиент не получил ответ из-за сетевой ошибки.

- Если предложение уже находится в состоянии `ACCEPTED`, повторный вызов возвращает `409 FRIENDSHIP_OFFER_ALREADY_ACCEPTED` и не меняет данные: вторая дружба и вторая подписка не создаются.
- Если предложение находится в состоянии `REJECTED`, попытка принять его возвращает `409 FRIENDSHIP_OFFER_ALREADY_REJECTED`.
- Если предложение не найдено, повторный вызов возвращает `404 FRIENDSHIP_OFFER_NOT_FOUND`.

## Возможные ошибки

Тело ответа с ошибкой: `{"code": "...", "message": "..."}`.

| HTTP-статус | `code` | Ситуация |
| --- | --- | --- |
| `400 Bad Request` | `INVALID_FRIENDSHIP_OFFER_REQUEST` | Некорректное тело запроса, отсутствует `offerId` или `actorId`, идентификатор не является UUID. |
| `404 Not Found` | `FRIENDSHIP_OFFER_NOT_FOUND` | Предложения нет или `actorId` не является его получателем. |
| `409 Conflict` | `FRIENDSHIP_OFFER_ALREADY_ACCEPTED` | Предложение уже принято. |
| `409 Conflict` | `FRIENDSHIP_OFFER_ALREADY_REJECTED` | Предложение уже отклонено. |
