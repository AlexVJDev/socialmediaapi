# Получение заявок в друзья текущего пользователя

Метод возвращает страницу заявок в друзья, в которых текущий пользователь — получатель (входящие) или отправитель (исходящие).

Входящие заявки показывают пользователю, что он может принять или отклонить; исходящие — кому он уже отправил предложение.
Текущий пользователь берётся из заголовка `X-User-Id` (временная замена токена до подключения Keycloak).

## HTTP-запрос

```http
GET /api/v1/friendship-offer?direction=INCOMING&status=PENDING&limit=20
X-User-Id: 5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22
Accept: application/json
```

## Заголовки

| Заголовок | Обязательный | Описание |
| --- | --- | --- |
| `X-User-Id` | Да | Идентификатор текущего пользователя (UUID). |

## Query-параметры

| Параметр | Тип | Обязательный | Описание |
| --- | --- | --- | --- |
| `direction` | `string` | Да | `INCOMING` — заявки, где текущий пользователь получатель; `OUTGOING` — где он отправитель. |
| `status` | `string` | Нет | Статус заявок: `PENDING` (по умолчанию), `ACCEPTED`, `REJECTED`. |
| `limit` | `integer` | Нет | Размер страницы, 1..100, по умолчанию 20. |
| `afterCreatedAt` | `string (date-time)` | Нет | `next.createdAt` предыдущей страницы; задаётся вместе с `afterId`. |
| `afterId` | `string (uuid)` | Нет | `next.id` предыдущей страницы; задаётся вместе с `afterCreatedAt`. |

## Успешный ответ

API возвращает статус `200 OK` и страницу заявок.

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "offers": [
    {
      "id": "2f6b9d13-8e4a-4b1c-a7d5-3c9e0f1b2a55",
      "fromUserId": "7d1f0a52-2b8e-4c9a-b3d6-4e8f1a2c5b66",
      "toUserId": "5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22",
      "status": "PENDING",
      "createdAt": "2026-09-22T10:25:00Z",
      "updatedAt": "2026-09-22T10:25:00Z"
    },
    {
      "id": "9c4e1b77-3f2a-4d6c-8b0e-1a5f7d2c3e44",
      "fromUserId": "0b6f3c9e-6a1d-4c2e-9f5a-2d7b8e1c4a01",
      "toUserId": "5e2a7d40-91c3-4b8f-a6e2-7c0d3f9b1e22",
      "status": "PENDING",
      "createdAt": "2026-09-22T10:15:00Z",
      "updatedAt": "2026-09-22T10:15:00Z"
    }
  ],
  "next": null
}
```

Если заявок нет, API возвращает пустую страницу.

```json
{ "offers": [], "next": null }
```

### Поля ответа

| Поле | Тип | Описание |
| --- | --- | --- |
| `offers` | `array` | Заявки страницы. |
| `offers[].id` | `string (uuid)` | Идентификатор заявки. |
| `offers[].fromUserId` | `string (uuid)` | Отправитель заявки. |
| `offers[].toUserId` | `string (uuid)` | Получатель заявки. |
| `offers[].status` | `string` | Статус заявки: `PENDING`, `ACCEPTED`, `REJECTED`. |
| `offers[].createdAt` | `string` | Дата и время создания заявки (ISO 8601). |
| `offers[].updatedAt` | `string` | Дата и время последнего изменения; для решённой заявки — время принятия или отклонения. |
| `next` | `object \| null` | Курсор следующей страницы `{createdAt, id}` — позиция последней заявки; `null` — заявок больше нет. |

## Правила обработки

- Возвращаются только заявки текущего пользователя: `direction=INCOMING` — где он получатель, `OUTGOING` — где отправитель.
- Фильтр `status` — одно значение; без параметра — `PENDING` (заявки, ожидающие решения).
- Порядок — от новых к старым: `createdAt DESC`, при равенстве — `id DESC`.
- Страницы читаются по курсору: первая — без `afterCreatedAt`/`afterId`, следующая — с `afterCreatedAt = next.createdAt` и `afterId = next.id`.
- Заявки, созданные после чтения первой страницы, на следующие страницы не попадают.
- Нет заявок или неизвестный пользователь — пустая страница, а не ошибка.

## Идемпотентность

Метод только читает данные и не изменяет состояние системы.

## Возможные ошибки

| HTTP-статус | Ситуация |
| --- | --- |
| `400 Bad Request` | `direction` нет или не из списка; `status` не из списка; `limit` вне 1..100 или не число; `afterCreatedAt` не дата-время; `afterId` не UUID; задана только одна часть курсора. |
| `401 Unauthorized` | Заголовок `X-User-Id` отсутствует или не UUID. |

Если некорректны и параметры, и заголовок `X-User-Id`, ответ — `400`: параметры проверяются раньше заголовка (до подключения Keycloak).
