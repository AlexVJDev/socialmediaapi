# Таблица переходов `OfferFriendship`

Документ описывает переходы заявки в друзья для команд `offerFriendship`, `acceptFriendship` и `rejectFriendship`.

## Переходы состояний

| Команда | Исходное состояние | Новое состояние | Изменение подписки | Изменение дружбы | Результат повторного вызова |
| --- | --- | --- | --- | --- | --- |
| `offerFriendship` | Заявка отсутствует | `PENDING` | Инициатор подписывается на получателя | Без изменений | `204 No Content`, состояние не меняется |
| `acceptFriendship` | `PENDING` | `ACCEPTED` | Получатель подписывается на инициатора, если обратной подписки ещё нет | Создаётся двусторонняя дружба между инициатором и получателем | `204 No Content`, состояние не меняется |
| `rejectFriendship` | `PENDING` | `REJECTED` | Без изменений: инициатор остаётся подписчиком получателя | Без изменений: дружба не создаётся | `204 No Content`, состояние не меняется |
| `offerFriendship` | `PENDING` | `PENDING` | Без изменений: инициатор уже подписан на получателя | Без изменений | `204 No Content`, состояние не меняется |
| `offerFriendship` | `ACCEPTED` | `ACCEPTED` | Без изменений: пользователи уже имеют необходимые подписки | Без изменений: дружба уже существует | `204 No Content`, состояние не меняется |
| `offerFriendship` | `REJECTED` | `REJECTED` | Без изменений: отклонённое предложение нельзя повторно перевести в `PENDING` | Без изменений | `409 Conflict`, `OfferFriendshipAlreadyRejectedException`, состояние не меняется |
| `acceptFriendship` | `ACCEPTED` | `ACCEPTED` | Без изменений: обратная подписка уже существует или уже должна быть создана | Без изменений: дружба уже существует | `204 No Content`, состояние не меняется |
| `rejectFriendship` | `ACCEPTED` | `ACCEPTED` | Без изменений | Без изменений: уже созданная дружба не отменяется командой отклонения | `409 Conflict`, `RejectFriendshipAlreadyAcceptedException`, состояние не меняется |
| `acceptFriendship` | `REJECTED` | `REJECTED` | Без изменений | Без изменений: отклонённая заявка не создаёт дружбу при повторном принятии | `409 Conflict`, `AcceptedFriendshipAlreadyreRejectedException` состояние не меняется |
| `rejectFriendship` | `REJECTED` | `REJECTED` | Без изменений | Без изменений: дружба не создана | `204 No Content`, состояние не меняется |

## Правила идемпотентности

- Повторный вызов команды не должен создавать дублирующие заявки, подписки или связи дружбы.
- Если целевое состояние уже достигнуто, система возвращает `204 No Content` и не изменяет данные.
- Повторный `offerFriendship` для заявки в состоянии `PENDING` возвращает `204 No Content`, потому что заявка уже ожидает решения.
- Повторный `offerFriendship` для заявки в состоянии `ACCEPTED` возвращает `204 No Content`, потому что дружба уже существует.
- Повторный `offerFriendship` для заявки в состоянии `REJECTED` возвращает `409 Conflict` через `OfferFriendshipAlreadyRejectedException`, потому что отклонённое предложение нельзя повторно перевести в `PENDING`.
- Отклонение заявки не отменяет подписку инициатора на получателя.
- Принятие заявки создаёт дружбу и обратную подписку атомарно.

## Ошибочные ситуации

Для каждой ошибочной ситуации используется отдельный тип исключения. Это явно передаёт причину отказа и позволяет внешнему слою выбрать подходящий HTTP-ответ.

| Ситуация | Команда | Исходное состояние | Новое состояние | Изменение подписки | Изменение дружбы | Исключение |
| --- | --- | --- | --- | --- | --- | --- |
| Пользователь предлагает дружбу самому себе | `offerFriendship` | Заявка отсутствует | Без изменений | Без изменений | Без изменений | `OfferFriendshipToSelfException` |
| Предложение для принятия не найдено | `acceptFriendship` | Заявка отсутствует | Без изменений | Без изменений | Без изменений | `FriendshipRequestNotFoundException` |
| Предложение для отклонения не найдено | `rejectFriendship` | Заявка отсутствует | Без изменений | Без изменений | Без изменений | `FriendshipRequestNotFoundException` |
| Повторное предложение после отклонения | `offerFriendship` | `REJECTED` | `REJECTED` | Без изменений | Без изменений | `OfferFriendshipAlreadyRejectedException` |

## Повторное предложение дружбы после отклонения

После состояния `REJECTED` повторный вызов `offerFriendship` не создаёт новое предложение и завершается конфликтом.

Если продукту понадобится разрешить повторное предложение через некоторое время, для этого потребуется отдельное бизнес-правило. Такое правило должно явно описывать, когда отклонённое предложение можно заменить новым, например после истечения периода ожидания.
